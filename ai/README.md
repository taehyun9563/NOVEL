# AI 공동 설계 운영

Claude와 ChatGPT가 같은 작품을 함께 설계할 때의 공통 규칙. 각 AI의 프로젝트 지침은 이 폴더의 파일을 원본으로 하며, 수정은 여기서 먼저 하고 프로젝트 설정에 다시 붙여넣는다.

| [`chatgpt_프로젝트_지침.md`](chatgpt_프로젝트_지침.md) | ChatGPT 프로젝트 지침 |

## 역할

| 주체 | 역할 |
| --- | --- |
| Claude | 기본값: 메인 작가 · 총괄 기획 — 설계, 집필, RP, 의견 조율 |

## 작품별 역할 예외 (사용자 결정 2026-11-20)

- 작품별 설계·검수 역할은 사용자가 지정한다. 기본값은 **Claude 설계·ChatGPT 검수**다.
- **06 정통판타지_번개** (`stories/06_정통판타지_번개/`)는 **ChatGPT 설정 설계 → Claude 독립 검수 → ChatGPT 의견별 조율 → 사용자 최종 승인**으로 운영한다.
- **06의 설계·검수 역할 예외는 06 작품에만 적용**한다. 07 이후의 신작에 자동 확장하지 않는다.
- 본문 집필·RP 담당은 설정 설계 역할과 별도로 지정한다. **작품 06의 본문 집필·RP 진행 담당은 ChatGPT 확정(D-023)**.
- **작품 07 북부대공 빙제의 본문 집필·RP 담당도 사용자 결정으로 ChatGPT 확정(D-022)**. 이 지정이 06의 설계·검수 역할 예외를 07에 복사한다는 뜻은 아니다.
- **작품 08 현대판타지 길드 성장**의 본문 집필·RP 진행 담당도 **ChatGPT 확정(D-028)**. 작품 08의 전용 운영 규칙은 `stories/08_현대판타지_길드성장/settings/11_RP_운영.md` v1.2다. 집필 담당 예외는 설정 설계·검수 역할 변경을 의미하지 않는다.
- **작품 06·07·08은 각 작품의 별도 `RP 시작` 요청 전까지 본편을 시작하지 않는다.**
- 작품별 원본 `settings/`·`DECISIONS.md`의 최신 승인 사항을 우선한다.

## 절차 (기본 1라운드)

1. **담당 설계 AI 초안** — 설계안 + 독립 검수 AI용 「검토 요청서」
2. **담당 검수 AI 독립 검수** — 저장소 원본 `settings/`·`DECISIONS.md`와 대조
3. **담당 설계 AI 조율** — 의견별 판정(수용 / 일부 수정 수용 / 미수용 / 추가 논의) + 수정안
4. **사용자 승인** — 확정할 항목만 선택
5. **저장소 반영** — `settings/` 갱신 및 필요한 경우 `DECISIONS.md`에 새 D-번호 기록

- **중요 설정**(세계관·경지·핵심 능력·주요 인물 관계·중요 서사 분기)은 검수 후 사용자 승인을 기본으로 한다.
- **경미한 문서 정리**(오탈자, 링크, 낡은 미정 표기의 최신 결정 동기화 등 의미 변경이 없는 작업)는 간소화하며, 새 D-번호나 추가 독립 검수를 강제하지 않는다.
- 확정 설정의 실질적인 의미가 바뀌면 신규 D-번호를 발급하며 기존 D-번호를 덮어쓰지 않는다.
- 중요 쟁점만 추가 검수를 진행한다. 같은 쟁점을 이유 없이 반복 검토하지 않는다.
- 이미 승인된 06의 D-000~D-008은 소급하여 무효화하지 않는다.

## 공통 원칙

### 반론 검토
- 상대 의견을 판정하기 전에, 그 의견이 옳다고 가정했을 때 가장 강한 근거를 먼저 쓴다.
- 어느 설계 AI든 상대 검수 의견을 미수용할 경우, **미수용 의견과 반대 근거를 반드시 사용자에게 공개**한다. 최종 결정은 사용자에게 있다.

### 설정 확장 억제
1. 새 설정을 추가하기 전에 기존 설정으로 해결할 수 있는지 먼저 검토한다.
2. 기존 설정의 확장·보완으로 해결되면 새 능력·경지·조직·인물을 만들지 않는다.
3. 새 설정이 꼭 필요하면 기존 설정만으로 안 되는 이유를 설명한다.
4. "개선 제안"이라는 이유만으로 설정을 늘리지 않는다.
5. 확정 설정과 충돌하는 제안은 따로 표시한다.
6. 사용자가 승인하지 않은 신규 설정은 확정하지 않는다.

### 설정 관리
- **`settings/` 파일** — 설정 내용의 유일한 원본. 추천·미정은 표시를 붙여 구분한다(저장소 공통 규칙).
- **`DECISIONS.md`** — 결정 이력만 쓴다. 상세 내용은 쓰지 않고 `settings/` 위치를 연결한다.
- 상태: `확정` / `추천` / `미정` / `대체됨 → D-xxx` / `폐기`
- 확정 설정을 바꿀 때는 기존 항목을 고치지 않고 **새 D-번호**를 만든다. 기존 항목은 `대체됨 → D-새번호`로 표시한다.
- 요약에는 **바뀐 내용 자체**를 쓴다. ("새 체계로 변경" ✗ → "졸업 전 최대 4경지, 돌파는 실전 기반" ○)
- 제안자(사용자 / Claude / ChatGPT)를 기록한다.

### RP
- 평소 RP는 Claude가 메인 작가로 진행하는 것을 기본으로 하되, 작품별 사용자 지정이 우선한다.
- 작품 06의 RP 집필 담당은 **ChatGPT**(D-023), 작품 07도 **ChatGPT**(D-022), 작품 08도 **ChatGPT**(D-028)다. 기존 **Claude 독립 검수** 및 사용자 최종 결정 체계는 유지된다.
- 공동 설계는 사용자가 요청하거나 확정 설정 변경이 필요할 때만 한다.

## 신규 차원전쟁 귀환물 — 최소 설계·등장 시 기록 원칙 (사용자 지시 2026-11-23)

> 적용 범위: 현재 설계 중인 **중앙 차원·지구·신계·마계 차원전쟁 귀환물**에만 적용한다. 다른 기존 작품의 운영 규칙을 변경하지 않는다. 작품 폴더와 번호는 별도 승인 전까지 만들지 않는다.

- **사전 세계관 설계는 최소화한다.** 국가·세력은 우선 **명칭과 한 줄 성격/역할** 정도만 정한다. 세부 국가사, 제도, 왕실 계보, 조직도, 지역명, 인물 명단을 미리 대량으로 만들지 않는다.
- **등장 시 확장한다.** 해당 국가의 **이름 있는 인물이 본편/RP에 처음 실제 등장**했을 때만 필요한 최소 설정(인물 이름, 소속 국가·세력, 역할/지위, 장면에서 드러난 성격·관계·능력)을 정리한다. 미등장 인물이나 국가의 빈 설정을 선제적으로 채우지 않는다.
- **GitHub 기록:** 인물이 처음 등장한 뒤 해당 작품의 `settings/` 인물·국가 원본에 등장으로 확인된 사실을 기록하고, 등장 회차·주요 행동은 `progress/`에 남긴다. 이후 관계·지위·능력 등 실질적으로 바뀐 내용만 갱신하며 **단순 재등장마다 중복 기록하거나 커밋하지 않는다.** 사용자의 이 지시를 해당 작품의 등장 인물 기록·저장에 대한 사전 승인으로 본다.
- **확정과 제안 구분:** 실제 RP에서 확립된 사실과 사용자 승인 사항만 정사로 기록한다. 미등장 설정·AI 추정·검수 중인 제안은 [제안]으로 구분한다. 핵심 세계관·능력 체계·주요 관계의 변경은 기존 승인·검수·새 D-번호 원칙을 따른다. 단순 인물 등장과 장면 기록만을 위해 D-번호를 남발하지 않는다.
- **운영 시점:** 본편/RP는 별도 사용자 시작 요청 전까지 시작하지 않는다. 작품 폴더가 생성되면 이 원칙을 그 작품의 RP 운영 문서에 반영한다. GitHub 저장에 실패하거나 접근할 수 없다면 저장한 것으로 주장하지 말고 사용자에게 알린다.
