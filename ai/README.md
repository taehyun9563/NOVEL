# AI 공동 설계 운영

Claude와 ChatGPT가 같은 작품을 함께 설계할 때의 공통 규칙. 각 AI의 프로젝트 지침은 이 폴더의 파일을 원본으로 하며, 수정은 여기서 먼저 하고 프로젝트 설정에 다시 붙여넣는다.

| 파일 | 용도 |
| --- | --- |
| [`claude_프로젝트_지침.md`](claude_프로젝트_지침.md) | Claude 「선호」 프로젝트 지침에 추가할 내용 |
| [`chatgpt_프로젝트_지침.md`](chatgpt_프로젝트_지침.md) | ChatGPT 프로젝트 지침 |
| [`프롬프트.md`](프롬프트.md) | 매번 쓰는 프롬프트 3종 |

## 역할

| 주체 | 역할 |
| --- | --- |
| Claude | 메인 작가 · 총괄 기획 — 설계, 집필, RP, 의견 조율 |
| ChatGPT | 독립 검수자 — 검증, 비평, 대안, 정합성 |
| 사용자 | 최종 결정권자 — 확정, 변경, 폐기 |
| GitHub (이 저장소) | 단일 기준 — 설정 원본, 결정 이력, 버전 관리 |

## 절차 (기본 1라운드)

1. **Claude 초안** — 설계안 + ChatGPT용 「검토 요청서」
2. **ChatGPT 검수** — 저장소 원본 `settings/`와 대조해 독립 검토
3. **Claude 조율** — 의견별 판정(수용 / 일부 수용 / 미수용 / 추가 논의) + 수정안
4. **사용자 승인** — 확정할 것만 고름
5. **저장소 반영** — `settings/` 갱신 + `DECISIONS.md`에 D-번호 기록

중요한 설정·분기만 1라운드를 더 돈다. 같은 쟁점을 이유 없이 반복 검토하지 않는다.

## 공통 원칙

### 반론 검토
- 상대 의견을 판정하기 전에, 그 의견이 옳다고 가정했을 때 가장 강한 근거를 먼저 쓴다.
- Claude가 미수용한 ChatGPT 의견은 근거와 함께 **반드시 사용자에게 보여준다.** Claude가 혼자 폐기하지 않는다.

### 설정 확장 억제
1. 새 설정을 추가하기 전에 기존 설정으로 해결할 수 있는지 먼저 검토한다.
2. 기존 설정의 확장·보완으로 해결되면 새 능력·경지·조직·인물을 만들지 않는다.
3. 새 설정이 꼭 필요하면 기존 설정만으로 안 되는 이유를 설명한다.
4. "개선 제안"이라는 이유만으로 설정을 늘리지 않는다.
5. 확정 설정과 충돌하는 제안은 따로 표시한다.
6. 사용자가 승인하지 않은 신규 설정은 확정하지 않는다.

### 설정 관리
- **`settings/` 파일** — 설정 내용의 유일한 원본. 추천·미정은 표시를 붙여 구분한다(저장소 공통 규칙).
- **`DECISIONS.md`** — 결정 이력만 쓴다. 상세 내용은 쓰지 않고 `settings/` 위치를 연결한다.
- 상태: `확정` / `추천` / `미정` / `대체됨 → D-xxx` / `폐기`
- 확정 설정을 바꿀 때는 기존 항목을 고치지 않고 **새 D-번호**를 만든다. 기존 항목은 `대체됨 → D-새번호`로 표시한다.
- 요약에는 **바뀐 내용 자체**를 쓴다. ("새 체계로 변경" ✗ → "졸업 전 최대 4경지, 돌파는 실전 기반" ○)
- 제안자(사용자 / Claude / ChatGPT)를 기록한다.

### RP
- 평소 RP는 Claude가 메인 작가로 진행한다.
- 공동 설계는 사용자가 요청하거나 확정 설정 변경이 필요할 때만 한다.
